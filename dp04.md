# 1049. Last Stone Weight II
```java
class Solution {
    public int lastStoneWeightII(int[] stones) {
        // The idea:
        // This problem is equivalent to splitting stones into two groups such that
        // the difference of their total weights is minimized.
        // This is similar to the "Partition Equal Subset Sum" problem — a subset sum DP problem.

        // dp[i] means: is it possible to achieve a subset sum of weight i using some stones.
        boolean[] dp = new boolean[2501];
        dp[0] = true; // Base case: subset sum 0 is always possible (by choosing nothing)

        int sum = 0; // total sum of all stones
        for (int num : stones) {
            sum += num; // accumulate total sum

            // Key insight:
            // We traverse backwards to avoid using the same stone multiple times.
            // If we went forward, dp[i - num] could be updated in the same iteration and reused incorrectly.
            for (int i = Math.min(2500, sum); i >= num; i--) {
                // Transition:
                // If we can form sum (i - num), then we can also form sum i by adding this stone.
                dp[i] = dp[i] || dp[i - num];
            }
        }

        // After processing all stones, we want the subset whose sum is closest to sum/2.
        // Because if we can get subset1 = i, then subset2 = sum - i.
        // The difference between them = (sum - i) - i = sum - 2*i.
        // So minimizing the difference is equivalent to maximizing i <= sum/2 that is achievable.
        for (int i = sum / 2; i >= 0; i--) {
            if (dp[i]) {
                // Found the largest possible subset sum <= sum/2.
                // Return the minimum possible difference between the two groups.
                return sum - i - i;
            }
        }

        // In theory, we’ll always return inside the loop, but for completeness:
        return 0;
    }
}
```
Time Complexity: O(n * sum) where sum ≤ 3000 (since each stone ≤ 100)

Space Complexity: O(sum) since we use a 1D boolean DP array.
# 494. Target Sum
```java
class Solution {
    public int findTargetSumWays(int[] nums, int target) {
        // High-level idea (what I'd say in an interview):
        // We are assigning either '+' or '-' in front of each number in nums.
        // Each assignment leads to some total sum. We want to count how many
        // different assignments lead exactly to `target`.
        //
        // I use DP where:
        //   dp[i][s] = number of ways to reach sum "s-offset" using nums[0..i]
        // because sums can be negative, I shift them by an offset.

        // Step 1: Compute the total sum of all numbers.
        // This gives us the maximum absolute sum we could possibly reach.
        int sum = 0;
        for (int num : nums) {
            sum += num;
        }

        int n = nums.length;

        // Optimization: if |target| > sum, it's impossible to reach target.
        // (Even if we put all '+' or all '-' we can't reach that magnitude.)
        if (Math.abs(target) > sum) {
            return 0;
        }

        // Step 2: Build a 2D DP table.
        // Possible sums range from -sum to +sum, inclusive → that's (2*sum + 1) possible sums.
        // We use an offset = sum, so index 0 represents sum = -sum, and index 2*sum represents sum = +sum.
        //
        // dp[i][k] = number of ways to reach sum (k - sum) using nums[0..i].
        int[][] dp = new int[n][2 * sum + 1];

        // Step 3: Initialize DP for the first element nums[0].
        // We have two choices for the first number:
        //   +nums[0]  → sum = nums[0]
        //   -nums[0]  → sum = -nums[0]
        //
        // We map these sums into indices by adding offset "sum".
        dp[0][nums[0] + sum] += 1;
        dp[0][-nums[0] + sum] += 1;
        // Note: if nums[0] == 0, +0 and -0 are the same sum 0,
        // so dp[0][sum] becomes 2 (two distinct sign assignments).

        // Step 4: Fill the DP table for the remaining elements.
        // currSum will track the maximum absolute sum reachable using nums[0..i].
        // This lets us tighten the inner loop bounds and avoid scanning the full [-sum, sum] range.
        int currSum = nums[0];

        for (int i = 1; i < n; i++) {
            // After including nums[i], the absolute maximum sum reachable
            // (if we chose all '+' or all '-') becomes:
            currSum += nums[i];

            // For i-th element, the reachable sums are in [-currSum, currSum].
            // We iterate over all possible previous sums `j` in that range.
            for (int j = -currSum; j <= currSum; j++) {
                // Map the logical sum j to an index in dp using offset.
                int prevIndex = j + sum;

                // We must ensure index is in bounds, because for smaller i
                // currSum might be smaller than total sum.
                if (prevIndex < 0 || prevIndex > 2 * sum) {
                    continue; // skip invalid index
                }

                // If there are no ways to get sum j using nums[0..i-1],
                // no need to expand this state.
                if (dp[i - 1][prevIndex] == 0) {
                    continue;
                }

                // Now, from sum j using first (i-1) elements, we can either:
                //   1) Add nums[i]  → new sum = j + nums[i]
                //   2) Subtract nums[i] → new sum = j - nums[i]
                //
                // We'll update the corresponding positions in dp[i].
                int ways = dp[i - 1][prevIndex];

                int plusSum = j + nums[i];
                int minusSum = j - nums[i];

                // Convert logical sums to indices (still using offset "sum").
                int plusIndex = plusSum + sum;
                int minusIndex = minusSum + sum;

                // Both plusIndex and minusIndex are guaranteed to be in [0, 2*sum],
                // because |plusSum|, |minusSum| ≤ currSum ≤ sum.
                dp[i][plusIndex] += ways;
                dp[i][minusIndex] += ways;
            }
        }

        // Step 5: Our answer is the number of ways to get `target` using all n elements.
        // The logical sum "target" corresponds to index (target + sum).
        return dp[n - 1][target + sum];
    }
}
```
TC: O(n * S) — proportional to number of elements times possible sum range.

SC: O(n * S) → can be optimized to O(S) using 1D DP.
# 474. Ones and Zeroes
```java
class Solution {

    // As an interviewee, I'd start with a high-level summary:
    // We are given a list of binary strings and two limits: 
    //   m = max number of '0's we can use,
    //   n = max number of '1's we can use.
    // We want to pick the largest possible subset of these strings such that
    // the total number of '0's ≤ m and total number of '1's ≤ n.
    //
    // This is a classic 0/1 knapsack variant with TWO capacities (zeros and ones).
    // I solve it using 3D DP: dp[i][j][k] = max number of strings we can form
    // using the first (i + 1) strings, with at most j zeros and k ones.
    public int findMaxForm(String[] strs, int m, int n) {

        // dp[i][j][k]:
        //   i: index of string we have considered up to (0..strs.length-1)
        //   j: how many zeros we are allowed to use (0..m)
        //   k: how many ones we are allowed to use  (0..n)
        // Value: maximum number of strings that can be formed under these limits.
        int[][][] dp = new int[strs.length][m + 1][n + 1];

        // --- Base case initialization for the first string (i = 0) ---

        // Count zeros and ones in the first string
        int firstcount1 = findCharCount(strs[0], '1');
        int firstcount0 = findCharCount(strs[0], '0');

        // If the first string itself fits within the capacity (m, n),
        // then the best we can do using only this string and capacities
        // (firstcount0, firstcount1) is to pick exactly this 1 string.
        if (firstcount0 <= m && firstcount1 <= n) {
            dp[0][firstcount0][firstcount1] = 1;
        }

        // --- Fill DP for the rest of the strings (i from 1 to end) ---

        // We iterate over each string as an item in a 0/1 knapsack
        for (int i = 1; i < strs.length; i++) {

            // Count zeros and ones in the current string strs[i]
            int count1 = findCharCount(strs[i], '1');
            int count0 = findCharCount(strs[i], '0');

            // For each capacity of zeros j and ones k, we decide:
            //   - NOT take strs[i], or
            //   - TAKE strs[i] (if it fits).
            for (int j = 0; j <= m; j++) {
                for (int k = 0; k <= n; k++) {

                    // Option 1: Do NOT pick the i-th string.
                    // Then the best result is the same as using only first (i-1) strings.
                    dp[i][j][k] = dp[i - 1][j][k];

                    // Option 2: Pick the i-th string (if it fits).
                    // That means:
                    //   - we must have enough capacity: j >= count0 and k >= count1
                    //   - if we pick it, we add 1 to the solution of
                    //     "using first (i-1) strings with reduced capacities
                    //      (j - count0, k - count1)".
                    if (count0 <= j && count1 <= k) {
                        dp[i][j][k] = Math.max(
                            dp[i][j][k],                                   // not picking
                            dp[i - 1][j - count0][k - count1] + 1         // picking
                        );
                    }
                }
            }
        }

        // --- Extract the answer ---

        // After processing all strings, the answer is the maximum value
        // in the last layer dp[strs.length - 1][*][*], because we can use
        // up to m zeros and n ones, and we want the best over ALL such capacities.
        int max = 0;
        for (int j = 0; j <= m; j++) {
            for (int k = 0; k <= n; k++) {
                max = Math.max(max, dp[strs.length - 1][j][k]);
            }
        }

        return max;
    }

    // Helper function to count how many times a particular character appears in a string.
    // I keep this as a separate method for clarity and reuse.
    public int findCharCount(String str, char ch) {
        int count = 0;

        // Iterate over each character in the string
        for (char c : str.toCharArray()) {
            // If it matches the target character, increment the counter
            if (c == ch) {
                count++;
            }
        }

        // Return the total number of occurrences
        return count;
    }
}

```
Time complexity:
We have len = strs.length, and for each string we iterate over all (m + 1) * (n + 1) states,
so time is O(len * m * n).

Space complexity:
Here it’s O(len * m * n) because of the 3D DP array.
We can optimize to O(m * n) using a 2D DP and iterating j and k backwards for each string (so we don’t overwrite states we still need in the same iteration), similar to a 0/1 knapsack optimization.
